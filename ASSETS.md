# Asset licensing

This repository ships **code only**. No 3D model, motion clip, or texture is
included. This document records what the runtime expects, the terms of each
source, and how to publish assets legally.

## What the scene expects

| Kind | Expected path (when supplied by the user) | Notes |
|---|---|---|
| Room | `tools/layout-model-v3/dist/apartment-v3.glb` | Built from `layout.json` by the project's exporter |
| Avatar | `tools/layout-model-v3/web/npc/assets/models/avatar.vrm` | Any VRM 0.x / 1.0 humanoid |
| Clips | `stage/public/animations/npc/*.json` | Baked from BVH; loop metadata required |

## Terms by source

### 1. VRoid sample models — usable, but not CC0

`AvatarSample_A/B/C` come from VRoid's sample set. VRoid's published conditions
say the files may be used by anyone for any activity, for-profit or not, with
no attribution required. Prohibited acts include:

- distributing the sample model or its VRM file while designating it **CC0**;
- redistributing the `.vroid`/VRM file **for a fee**;
- using the data to build or feed a character-creation service.

Practical consequence: you may ship it with a project for free, but you must
keep the VRoid terms attached and must not relicense it as MIT/CC0. The safest
public-repo pattern is **not to bundle it** and instead point users at VRoid
Hub or their own model.

Source: <https://vroid.pixiv.help/hc/en-us/articles/4402394424089>

### 2. CMU Motion Capture Database — redistributable with attribution

CMU's terms: the data may be copied, modified, or redistributed without
permission; it may be included in commercially sold products, but the data
itself may not be resold directly, even in converted form.

Required attribution:

> The data used in this project was obtained from mocap.cs.cmu.edu.
> The database was created with funding from NSF EIA-0196217.

Consequence: baked clips derived from CMU may live in a public repository if
the attribution and the no-direct-resale rule are preserved. Do **not** put
them under the repository's MIT license; give them their own asset license.

### 3. Mixamo-derived animation — excluded

Mixamo output used during development (the `*.vrma` set) is governed by Adobe's
terms and the upstream Clawatar project's own note that those clips are for
non-commercial demonstration. They are excluded from this repository and must
not be redistributed as standalone files.

### 4. Poly Haven textures — CC0

Environment textures sourced from Poly Haven are CC0 and may be redistributed.
Keep a manifest entry with the original URL for provenance even though
attribution is not required.

### 5. BlueFatFish / third-party character models — excluded

Community models (for example the DeepSeek whale character) carry
author-specific terms; some are authorized only for distribution *with a
specific plugin*, not for general redistribution. They are not part of this
repository.

## How to open-source the assets

You cannot relicense someone else's model. Pick one of three routes per asset:

### Route A — publish your own work (recommended)

1. Create the model in VRoid Studio / Blender yourself, or commission it with a
   written transfer of rights.
2. Release it under **CC0-1.0** or **CC-BY-4.0** in a separate `assets` repo or
   release asset (not mixed into the MIT code license).
3. Include a `LICENSE-ASSETS` file, a manifest with `sha256`, and a provenance
   line (tool, date, author).

This is the only route that gives users a fully reproducible, legally clean
checkout.

### Route B — redistribute permissively licensed third-party assets

1. Keep the original license text next to the asset.
2. Record source URL, author, download date, and `sha256` in a manifest.
3. Do not describe the asset as MIT; the repository LICENSE covers code only.
4. For CMU data, include the attribution sentence above.

### Route C — do not redistribute; fetch or require user supply

1. Ship a `scripts/fetch-assets.py` that downloads only from sources whose
   terms allow it.
2. For models like VRoid samples, print the terms and a link instead of
   downloading automatically.
3. At runtime, fail with a clear message if the asset is missing; never
   substitute a placeholder and pretend it is the real model.

### Suggested split for AgentRoom

| Asset | Route | License to publish under |
|---|---|---|
| `apartment-v3.glb` (generated by this project) | A | CC0-1.0 |
| Room textures from Poly Haven | B | CC0-1.0 (manifest only) |
| CMU-derived clips | B | CMU terms + attribution, separate file |
| Avatar used for demos | C (or A if you make one) | VRoid terms / your own CC0 |
| Mixamo-derived clips | excluded | — |

## Manifest format

```json
{
  "path": "assets/models/avatar.vrm",
  "sha256": "…",
  "source": "https://…",
  "author": "…",
  "license": "CC0-1.0",
  "retrieved": "2026-10-29"
}
```

Keep the manifest in the repository even when the asset itself is not, so
builds can verify what the user supplied.
